Privacy Policy

A clear explanation of the information used by our website and our private desktop application, ToolGlow Lab Automation.

Effective and last updated: November 14, 2026

1. Who we are and what this covers

ToolGlow Lab is an independently operated content and automation project focused on AI tools, productivity, automation, and useful technology. The project operator can be contacted at devyanshmalhotra28@gmail.com.

ToolGlow Lab Automation is a privately operated desktop automation system used to generate original videos locally, upload them to an authorized YouTube channel, and check uploaded videos’ processing status. It uses YouTube API Services and Google OAuth authorization. It is not offered as a public SaaS service.

This policy covers the public informational website and that desktop workflow. The website does not perform Google sign-in, request channel access, or receive OAuth tokens.

2. Information from website visits and contact

This static website has no accounts, forms, analytics scripts, advertising scripts, embedded video players, cookies, or browser-storage features added by ToolGlow Lab.

The site is hosted on GitHub Pages. GitHub processes technical request information, including visitors’ IP addresses, to provide and secure its hosting service. See the GitHub Privacy Statement for GitHub’s practices and retention.

If you email us, we receive your email address, the contents of your message, and any information you choose to include. That correspondence is used to respond to your inquiry or handle your request and is kept as needed for that purpose and relevant records. Please do not send passwords, OAuth credentials, or tokens.

3. Google OAuth permissions

The desktop application requests authorization from the channel owner through Google’s OAuth flow. Google handles account authentication; ToolGlow Lab Automation does not ask for or store your Google account password.

The requested permissions are:

https://www.googleapis.com/auth/youtube.upload
Used to upload locally generated original videos and their upload metadata to the authorized YouTube channel. Google may describe this permission more broadly as managing YouTube videos; the application’s stated use is video uploading.
https://www.googleapis.com/auth/youtube.readonly
Used to read YouTube information associated with the authorized channel and uploaded videos, including video identifiers and processing or upload status, so the workflow can check whether uploads have processed. This scope permits broader read access than the specific status checks performed by this workflow.

Authorizing these permissions does not grant access to your Gmail messages, Google Drive files, or other unrelated Google services.

4. Data accessed and how it is used

The desktop workflow uses:

  • OAuth credentials, access tokens, and refresh tokens: to establish and maintain the authorization needed for YouTube API requests.
  • Locally generated videos and upload metadata: the video file and information such as its title, description, and upload settings are sent to YouTube as part of the upload.
  • YouTube API responses: identifiers for the authorized channel and uploaded videos, relevant video metadata, and processing or upload-status information are used to associate uploads with the channel and check their results.

Google and YouTube receive the API requests, authorization information needed to process those requests, and the content submitted for upload. Uploaded content’s visibility is governed by its YouTube settings.

Google user data is used for the authorized upload and processing-status workflow. It is not sold, used for advertising or profiling, shared with unrelated third parties, or used to train AI models. Generating original videos locally is separate from using API responses to track uploads.

5. Storage and access

OAuth credentials and tokens are stored locally in protected files on the operator’s computer. They are not part of this public website or its repository. API response information retained for the desktop workflow is handled locally; this website provides no hosted database for it.

The project operator handles the local files needed to operate and maintain the private workflow. Protection depends on the local computer and its file-access controls. This policy does not represent a security certification or a guarantee against unauthorized access.

6. Retention and deletion

Local tokens are retained while needed for the authorized workflow and must be removed when that access is no longer needed. Processing-status information is needed only for upload tracking. Any retained YouTube API response data must be removed when no longer necessary and deleted or refreshed within the applicable 30-calendar-day period under YouTube’s Developer Policies.

Deletion is handled manually by the project operator. This website does not provide an automatic token-deletion or local-file-cleanup feature. To request deletion of locally retained authorization or API data, email devyanshmalhotra28@gmail.com with the subject “ToolGlow Lab data deletion request” and identify the authorized channel. Do not attach credentials or tokens.

The operator’s procedure is to stop the affected workflow and remove its local tokens and retained API response data, including any such data in local logs or copies. YouTube’s policies require removal of stored user data as soon as possible and within seven calendar days following a deletion request or revocation of authorization. The operator is responsible for carrying out that process.

Removing local tokens or API records does not delete videos already uploaded to YouTube or original locally generated media. Manage or delete uploaded videos through YouTube Studio. Original local media can be removed separately by the operator. Google and GitHub handle data they retain under their own policies.

7. Your control and access revocation

You can decline authorization or stop using the desktop workflow. You can revoke the application’s Google account access at any time:

  1. Open your Google Account’s third-party connections settings.
  2. Select ToolGlow Lab Automation, or the application name shown when you authorized access.
  3. Review the connection and use Google’s option to remove its access or delete the connection.

Revocation prevents continued authorized API access, although an operation already submitted may have completed. It does not erase local files on the operator’s computer. Contact the operator using the deletion procedure above to have locally stored data removed. The application will require a new authorization before it can access the channel again.

8. Relevant third-party services

  • Google OAuth and YouTube API Services provide authorization, upload handling, and video-status responses. Read Google’s Privacy Policy and the YouTube Terms of Service.
  • GitHub Pages hosts the public website. Its handling of website-request data is covered by the GitHub Privacy Statement.
  • Gmail receives correspondence sent to the project’s contact address and is covered by Google’s Privacy Policy.

Following an external link takes you to that service, whose own privacy practices apply. This website does not load external fonts, analytics, or third-party media embeds.

9. Policy changes and contact

This policy may be updated as the project’s actual practices change. Updates will appear on this page with a revised date. Any future expansion of the app’s access or use of Google data must be disclosed before that expanded use and authorized where required.

For privacy questions, access concerns, or deletion requests, contact devyanshmalhotra28@gmail.com.
